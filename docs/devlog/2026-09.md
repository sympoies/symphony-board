## 2026-09-10 — Separate maintenance principles from detailed procedures

**Result**
- The root development guide is now a short entrypoint for architecture
  boundaries, routine workflow, and canonical documentation routing.
- Detailed toolchain, validation, testing, and change-path procedures have one
  owner under `docs/`, without dropping the existing operational guidance.

**Why / context**
- The previous root guide mixed stable maintenance principles with a long
  command inventory and implementation-specific runbooks. Separating those
  roles makes the contributor entrypoint easier to scan while keeping detailed
  procedures discoverable and independently maintainable.

**Evidence**
- Root `DEVELOPMENT.md` was reduced from 313 to 64 lines; the 315-line detailed
  reference preserves the relocated procedures.
- TypeScript type-check, the backend suite, 398 UI tests, the production UI
  build, render smoke, local Markdown links, and whitespace checks passed.
